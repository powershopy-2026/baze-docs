# PowerTokens CLI Usage Guide

PowerTokens CLI（command name `pt`, also supports `powertokens`）is used from the terminal to call the Chinese large language models, image models, video models, and speech models on the PowerTokens platform. It is suitable for local creation, bulk generation, script automation, and for invocation by coding agents.[1]

This document introduces the current features in the order “Install → Login → Select Model → Execute Tasks → Retrieve Files → Configuration and Troubleshooting”. The model catalog and vendor parameters are dynamically updated by the platform, so actual usage should rely on the results returned by `pt models`.

## 1. Quick Start

```bash
# Install
npm install -g powertokens-cli

# Configure API Key. If no argument is provided, an interactive prompt will be used
pt login

# Chat
pt chat "Explain quantum computing in one sentence"

# Generate image
pt generate 
  -m seedream-5-0-260128 
  -p "A cat wearing a spacesuit" 
  -o cat.png

# View available models
pt models
```

`pt generate` will automatically select the appropriate vendor route based on the model ID. Users do not need to manually specify the vendor endpoint.

## 2. Installation

### System requirements

PowerTokens CLI is distributed via npm. It is recommended to use Node.js 18 or later, and ensure that `npm` and the global npm executables directory are added to your system PATH.

```bash
node --version
npm --version
npm install -g powertokens-cli
```

After installation you can use the following two command names directly:

```bash
pt --version
powertokens --version
```

It is generally recommended to use the shorter `pt` command.

## 3. Login and Credential Management

### Login

```bash
# Interactively enter API Key
pt login

# Pass API Key directly
pt login sk-your-api-key-here
```

The API Key will be saved to the current user's local configuration file. Do not put the API Key into Git repositories, README files, frontend code, or shared logs.

### View current identity and usage information

```bash
pt whoami
```

This command is used to view the current login status, API Key prefix, API Base URL, and the number of available models, among other information. The command will not print the full API Key.

### Logout

```bash
pt logout
```

This command will remove the PowerTokens API Key stored on the local machine.

## 4. Recommended workflow

For unfamiliar models, the following process is recommended:

```text
models → choose a model → chat or generate → check local output
```

For automated scripts, the following process is recommended:

```text
read environment variables → check model → execute task → check exit status and output files
```

Model parameters are passed via `generate`'s general options and `--params`; the generated results are downloaded by the CLI to the path specified by `-o` after task completion.

## 5. View available models

```bash
# View all models
pt models

# View only chat models
pt models -t chat

# View only image models
pt models -t image

# View only video models
pt models -t video

# View only audio models
pt models -t audio
```

The model list is fetched dynamically from the PowerTokens API's `GET /v1/models`. The client caches the model list; when the API is temporarily unavailable, the CLI can use a built-in fallback list.

Current models are roughly categorized by capability as follows:

| Type | Example models | Description |
| --- | --- | --- |
| Chat | `glm-5.3`、`glm-4.7-flash`、`glm-5`、`deepseek-v4-pro`、`qwen3-max`、`MiniMax-M3` | Text chat and text generation |
| Image | `dola-seedream-5-0-pro-260628`、`seedream-5-0-260128`、`seedream-4-5-251128`、`qwen-image-3.0-pro`、`kling-v3` | Text-to-image and some image-to-image capabilities |
| Video | `dreamina-seedance-2-5-260628`、`dreamina-seedance-2-0-260128`、`kling-video-o1`、`wan3.0-video`、`MiniMax-H3`、`viduq3-turbo` | Text-to-video, image-to-video, and reference material generation |
| Audio | `speech-2.6-hd`、`speech-02-hd` | Text-to-speech |

`kling-v3` and `kling-v3-omni` and other multimodal models may appear in both the image and video categories.

## 6. Text Chat: `pt chat`

### Basic Usage

```bash
# Use default model
pt chat "What is TypeScript?"

# Specify model
pt chat -m glm-5.3 "Write a short poem about spring"

# Specify system prompt
pt chat 
  -s "You are a rigorous technical writer" 
  "Explain the difference between REST API and GraphQL"

# Specify max output tokens
pt chat -t 2048 "Write a longer product introduction"
```

### Read prompt from standard input

When no positional argument is provided, `pt chat` reads content from standard input. Therefore it can be combined with other commands:

```bash
echo "Explain recursion and give a JavaScript example" | pt chat

cat prompt.txt | pt chat -m glm-5
```

### Parameters

| Option | Default | Description |
| --- | --- | --- |
| `-m, --model <model>` | `glm-4.7-flash` | Model ID |
| `-s, --system <prompt>` | None | System prompt |
| `-t, --max-tokens <n>` | `1024` | Max output tokens |
| `[prompt]` | None | User prompt; if omitted reads from stdin |

## 7. Multimedia generation: `pt generate`

`generate` is the unified entry for image, video, and audio generation. At minimum you should provide model ID, prompt, and output path:

```bash
pt generate 
  -m <model_id> 
  -p "<prompt>" 
  -o <output_path>
```

### 7.1 Image generation

```bash
# Text-to-image
pt generate 
  -m dola-seedream-5-0-pro-260628 
  -p "Cyberpunk city nightscape, cinematic lighting" 
  -o city.png

# Using Kling image model
pt generate 
  -m kling-v3 
  -p "An orange cat sitting on a windowsill" 
  -o cat.png

# Using Qwen image model
pt generate 
  -m qwen-image-3.0-pro 
  -p "Sci-fi city nightscape" 
  -o city.png

# Image-to-image
pt generate 
  -m kling-v3 
  -p "Keep the character's appearance unchanged and replace with a winter background" 
  --ref start_frame.jpg 
  -o out.png
```

Common image parameters:

| Parameter | Description |
| --- | --- |
| `-m, --model <model>` | Image model ID; default `seedream-5-0-260128` |
| `-p, --prompt <prompt>` | Image generation prompt |
| `-o, --output <path>` | Output file path |
| `-s, --size <size>` | Image size; available values vary by provider |
| `--negative-prompt <text>` | Negative prompt; support depends on the specific model |
| `--aspect-ratio <ratio>` | Image aspect ratio, e.g. `1:1`; support depends on the specific model |
| `--seed <n>` | Random seed; support depends on the specific model |
| `--num <n>` | Number of images to generate |
| `--watermark` | Enable watermark; support depends on the specific model |
| `--params <json>` | Pass provider parameters in JSON form |

Image sizes are not standardized across all providers. For example Seedream commonly uses `2048x2048`, Kling uses `1k`, `2k`, or `4k`, and Qwen/Wan may use `2048*2048` or `2K`. Refer to the official parameters of the target model.

Kling's `std`, `pro`, and `4k` indicate quality tiers and do not necessarily correspond to fixed pixel dimensions. The CLI maps these values to the parameters required by the upstream API.

### 7.2 Text-to-video

```bash
# Seedance
pt generate 
  -m dreamina-seedance-2-5-260628 
  -p "A dog running on a beach, camera smoothly tracking" 
  -o dog.mp4

# Wan
pt generate 
  -m wan3.0-video 
  -p "A cute little rabbit hopping on the grass" 
  -o wan.mp4

# MiniMax Hailuo
pt generate 
  -m MiniMax-H3 
  -p "A girl smiling and looking at the camera" 
  -r 768p 
  --ratio 21:9 
  -o hailuo.mp4
```

Common video parameters are as follows:

| Parameter | Default | Description |
| --- | --- | --- |
| `-r, --resolution <res>` | `720p` | Video resolution or provider quality tier |
| `-d, --duration <seconds>` | Determined by the model | Video duration in seconds |
| `--ratio <ratio>` | Determined by the model | Seedance aspect ratio; available `16:9`, `4:3`, `1:1`, `adaptive` |
| `--aspect-ratio <ratio>` | Determined by the model | Aspect ratio for models like Kling, Vidu, etc. |
| `--sound [on|off]` | Determined by the model | Kling video sound control |
| `--generate-audio` | off | Video audio generation option supported by Seedance, Vidu, etc. |
| `--watermark` | off | Whether to enable watermark |
| `--seed <n>` | Determined by the model | May be supported by models like Wan, Vidu, Seedream |

Resolution values differ among providers. Seedance/Wan commonly use `480p`, `720p`, `1080p`; Kling commonly uses `std`, `pro`, `4k`; Vidu commonly uses `540p`, `720p`, `1080p`; Hailuo commonly uses `768P`, `1080P`.

### 7.3 Image-to-video

```bash
# Use a local image as the first frame
pt generate 
  -m dreamina-seedance-2-5-260628 
  -p "Camera slowly pushes in, the subject naturally blinks" 
  --ref start_frame.jpg 
  -o out.mp4
```

`--ref` supports local file paths, public URLs, Base64, or `asset://` resource identifiers. The CLI will automatically handle asset formats according to the provider.

### 7.4 First-and-last-frame video

```bash
pt generate 
  -m dreamina-seedance-2-5-260628 
  -p "Smoothly transition from the first frame to the last frame" 
  --ref first.jpg 
  --last-frame last.jpg 
  -o out.mp4
```

Models or model series that currently support the first-and-last-frame mode include Seedance, MiniMax Hailuo, MiniMax H3, Kling, Wan, and Vidu. The first and last frames should be provided as a pair using `--ref` and `--last-frame`.

### 7.5 Reference video and reference audio

```bash
# Use reference video
pt generate 
  -m dreamina-seedance-2-5-260628 
  -p "Maintain the action rhythm and style of the reference video" 
  --ref-video ref.mp4 
  -o out.mp4

# Use reference audio
pt generate 
  -m dreamina-seedance-2-5-260628 
  -p "Generate lip-synced video based on the reference audio" 
  --ref-audio voice.mp3 
  -o out.mp4
```

Seedance and MiniMax H3 support multimodal reference video generation:

```bash
pt generate 
  -m dreamina-seedance-2-5-260628 
  -p "Generate a new video referencing image, video, and audio" 
  --ref ref-img.jpg 
  --ref-video ref.mp4 
  --ref-audio voice.mp3 
  -o out.mp4
```

First-frame, first-and-last-frame, and multimodal reference are different input scenarios. When using multimodal references, they should not be treated as ordinary first-frame mode.

### 7.6 Kling camera motion control

```bash
# Use convenience parameters
pt generate 
  -m kling-v3 
  -p "Keep the character's actions unchanged" 
  --ref char.jpg 
  --ref-video https://example.com/dance.mp4 
  --character-orientation image 
  -o out.mp4
```

You can also pass more camera control parameters via `--params`:

```bash
pt generate 
  -m kling-v3 
  -p "Keep the character's actions unchanged" 
  --ref char.jpg 
  --params '{
    "video_url": "https://example.com/dance.mp4",
    "character_orientation": "image",
    "keep_original_sound": "yes"
  }' 
  -o out.mp4
```

When `video_url` or `character_orientation` appear in `--params`, the CLI will automatically select Kling's camera control endpoint. `--character-orientation` can be set to `image` or `video`.

### 7.7 Text-to-speech

```bash
pt generate 
  -m speech-2.6-hd 
  -p "Hello, welcome to PowerTokens" 
  -o hello.mp3
```

MiniMax voice models can specify the voice name via `--voice`:

```bash
pt generate 
  -m speech-02-hd 
  -p "Welcome to PowerTokens CLI" 
  --voice <voice_name> 
  -o welcome.mp3
```

## 8. `generate` Complete parameters

| Option | Description |
| --- | --- |
| `-m, --model <model>` | Model ID; default `seedream-5-0-260128` |
| `-p, --prompt <prompt>` | Generation prompt |
| `-o, --output <path>` | Output file path |
| `-s, --size <size>` | Image size |
| `-r, --resolution <res>` | Video resolution or quality tier; default `720p` |
| `-d, --duration <seconds>` | Video duration |
| `--ref <path|url|base64|asset>` | Reference image or first frame |
| `--last-frame <path|url|base64|asset>` | Last frame |
| `--ref-video <path|url|base64>` | Reference video or action video |
| `--ref-audio <path|url|base64>` | Reference audio |
| `--character-orientation <image|video>` | Source of character orientation in Kling camera-motion control |
| `--asset-group-id <id>` | Asset group ID used for Seedance asset uploads |
| `--negative-prompt <text>` | Negative prompt |
| `--aspect-ratio <ratio>` | Aspect ratio for models like Kling, Vidu, etc. |
| `--seed <n>` | Random seed |
| `--num <n>` | Number of images |
| `--watermark` | Enable watermark |
| `--sound [on|off]` | Kling video sound |
| `--generate-audio` | Generate video with audio |
| `--ratio <ratio>` | Seedance video ratio |
| `--voice <voice>` | MiniMax TTS voice name |
| `--params <json>` | Additional vendor parameters, passed as JSON |

Whether a parameter takes effect depends on the target model and upstream vendor. The CLI maps common parameters to the corresponding endpoints; fields that cannot be expressed by common parameters should be passed via `--params`.

## 9. Using `--params` to pass-through model parameters

### Merge mode

When the JSON in `--params` does not contain a `content` or `media` array, the CLI will merge the JSON fields into the request body:

```bash
pt generate 
  -m kling-v3 
  -p "cat" 
  --params '{"image_reference":"face","aspect_ratio":"1:1"}' 
  -o cat.png
```

```bash
pt generate 
  -m dreamina-seedance-2-5-260628 
  -p "dog running on the beach" 
  --params '{"generate_audio":true,"watermark":false}' 
  -o dog.mp4
```

### Full request body mode

When `--params` directly contains a `content` or `media` array, the CLI will treat it as a full request body and will add the `model` field. You can omit `-p` in this case:

```bash
pt generate 
  -m dreamina-seedance-2-5-260628 
  --params '{
    "content": [
      {"type":"text","text":"Generate a smooth product showcase video"},
      {"type":"image_url","image_url":{"url":"asset://xxx"},"role":"first_frame"}
    ],
    "duration": 4,
    "resolution": "480p"
  }' 
  -o out.mp4
```

The JSON parameter should be wrapped in single quotes to prevent Bash from interpreting double quotes as shell syntax. In Windows PowerShell, adjust the quotes according to the shell rules.

## 10. Asset handling and vendor differences

### Local assets

`--ref`, `--last-frame`, `--ref-video`, and `--ref-audio` can all accept local files. The CLI converts them automatically according to the vendor:

- BytePlus Seedance first uploads the assets to the asset library and then passes them to the model using `asset://<id>`. A directly provided `asset://` path is passed through unchanged.
- MiniMax, Kling, Wan, Vidu, and HappyHorse usually convert local files to Base64 or a data URL. The specific encoding method is determined by the vendor adapter.

BytePlus Seedance asset uploads have filename-length requirements. The CLI automatically truncates filenames that are too long while preserving the extension, but short filenames without special characters are still recommended.

### Support for main video parameters

| Parameter | Seedance | MiniMax Hailuo | MiniMax H3 | Kling | Wan | Vidu |
| --- | --- | --- | --- | --- | --- | --- |
| `--last-frame` | Supported | Supported | Supported | Supported | Supported | Supported |
| `--ref-video` | Supported | Not supported | Supported | Supports camera movement | Partial r2v support | Not supported |
| `--ref-audio` | Supported | Not supported | Supported | Not supported | Supported | Not supported |
| `--negative-prompt` | Not supported | Not supported | Not supported | Supported | Supported | Not supported |
| `--watermark` | Supported | Supported | Supported | Supported | Supported | Supported |
| `--generate-audio` / `--sound` | Supported in some versions | Not supported | Not supported | Supports `--sound` | Not supported | Supported |
| `--seed` | Supported | Not supported | Not supported | Not supported | Supported | Supported |
| `--aspect-ratio` / `--ratio` | Supported | Not supported | Supported | Supported | Supported | Supported |

Vendor fields not listed here should be passed through using `--params`. The table shows the CLI's current adapter support and does not represent the complete capabilities of the upstream models.

## 11. Configuration

### View and modify configuration

```bash
# View current configuration
pt config

# Set API Base URL
pt config -b https://baze-api.powerbuyin.top

# Set asset repository Base URL
pt config -a https://powertokens.ai/api

# Reset API Base URL and asset repository Base URL
pt config --reset
```

By default, the asset repository address is automatically derived from the API Base URL. For example, when the API address is `https://baze-api.powerbuyin.top`, the asset repository address is commonly derived as `https://powertokens.ai/api`. You only need to manually override with `-a` when using a separate asset service.

### Local configuration file

The config file is located at:

```text
~/.powertokens/config.json
```

File permissions default to `0600`. Example structure:

```json
{
  "apiKey": "sk-...",
  "baseUrl": "https://baze-api.powerbuyin.top",
  "assetBaseUrl": "https://powertokens.ai/api"
}
```

Do not commit this file to version control or copy it into public environments.

### Environment variables

Environment variables take precedence over the config file; suitable for CI/CD, containers, and temporary tasks:

| Environment Variable | Description |
| --- | --- |
| `POWERTOKENS_API_KEY` | API Key, overrides the Key in the config file |
| `POWERTOKENS_BASE_URL` | API Base URL, overrides the address in the config file |
| `POWERTOKENS_ASSET_BASE_URL` | Asset repository Base URL, overrides the automatically derived address |
| `PT_DEBUG` | When set to `1`, outputs raw request body and task results to stderr |

Example:

```bash
POWERTOKENS_API_KEY="sk-..." 
pt chat "Generate a product launch title"
```

Debug example:

```bash
PT_DEBUG=1 pt generate 
  -m seedream-5-0-260128 
  -p "minimal product photo" 
  -o product.png
```

Debug output may include request parameters and resource URLs. Do not keep debug output in shared logs.

## 12. Script Automation

### Bash

```bash
#!/usr/bin/env bash
set -euo pipefail

: "${POWERTOKENS_API_KEY:?Please set POWERTOKENS_API_KEY first}"

pt generate 
  -m seedream-5-0-260128 
  -p "product photo of a glass teapot on a white background" 
  -s 2048x2048 
  -o ./outputs/teapot.png
```

### Node.js

```js
import { execFile } from "node:child_process";
import { promisify } from "node:util";

const execFileAsync = promisify(execFile);

const { stdout } = await execFileAsync("pt", [
  "generate",
  "-m", "seedream-5-0-260128",
  "-p", "a clean product photo of a glass teapot",
  "-o", "./outputs/teapot.png",
]);

console.log(stdout);
```

### Python

```python
import os
import subprocess

if not os.environ.get("POWERTOKENS_API_KEY"):
    raise RuntimeError("Please set POWERTOKENS_API_KEY first")

subprocess.run(
    [
        "pt", "generate",
        "-m", "seedream-5-0-260128",
        "-p", "a clean product photo of a glass teapot",
        "-o", "./outputs/teapot.png",
    ],
    check=True,
)
```

In scripts you should explicitly check the process exit code and whether the target file exists. Do not rely on terminal logs to determine whether a task succeeded.

## 13. Frequently Asked Questions

### 13.1 Prompt: API Key not configured

First run one of the following commands:

```bash
pt login
```

or:

```bash
export POWERTOKENS_API_KEY="sk-..."
```

Then use `pt whoami` to verify login status.

### 13.2 Model not found or parameters not applied

First check the current model directory:

```bash
pt models
pt models -t image
pt models -t video
```

Model ID must match the returned result exactly, including case. Different models support different sizes, aspect ratios, audio, seeds, and reference assets; when uncertain, consult the model parameters from the corresponding provider and pass them via `--params`.

### 13.3 Local files cannot be used as reference assets

Make sure the file path is correct and check the file type and size. It's recommended to use an absolute path or a relative path from the current directory:

```bash
pt generate 
  -m kling-v3 
  -p "Keep the subject and change the background" 
  --ref "$(pwd)/input.png" 
  -o output.png
```

If the target is Seedance, also ensure the filename is short, and confirm that the API Key has permission to use the asset library.

### 13.4 `--params` JSON parsing failed

Check the quotes and JSON format. Bash example:

```bash
pt generate 
  -m kling-v3 
  -p "cat" 
  --params '{"aspect_ratio":"1:1","watermark":false}' 
  -o cat.png
```

For complex requests, it's recommended to write the JSON to a file first and then read it via a shell variable to avoid errors from nested quotes.

### 13.5 How to view the underlying request

Set `PT_DEBUG=1`:

```bash
PT_DEBUG=1 pt generate -m kling-v3 -p "cat" -o cat.png
```

The request body and task results will be output to stderr, useful for diagnosing parameter mapping, asset uploads, and vendor routing issues.

### 13.6 Output file not generated

Ensure:

1. The directory specified by `-o` exists, or create the directory first.
2. The current model and input combination actually supports that task type.
3. The task was not rejected by an upstream model.
4. API Key, API Base URL, and asset library address are configured correctly.
5. Use `PT_DEBUG=1` to view task status and raw responses.
